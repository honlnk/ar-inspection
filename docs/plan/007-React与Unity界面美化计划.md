## 1. 目标与原则

在不改变计划 006 已验收功能的前提下，将管理端从基础表格页面整理为清晰的问题工作台，将移动端从调试感较强的默认控件整理为适合现场单手操作的巡检界面。视觉服务于信息层级和任务完成，不追求宣传页、插画、复杂动画或与原型无关的装饰。

本计划完成时必须同时证明：

1. React 登录、问题工作台、筛选、状态修改和实时反馈形成一致视觉体系，桌面与窄屏均无横向页面溢出。
2. Unity 登录、AR 主界面、上报表单、历史、设置等界面风格一致；户外可辨认，常用操作适合拇指触达。
3. 优先级和处理状态在文字、标签、颜色上的语义一致，不仅依赖颜色传达信息。
4. 所有加载、空数据、错误、断线、会话过期、保存中和权限不足状态都有完整布局，不只美化成功路径。
5. UI 改动不引起业务、AR 输入、防误触、实时同步、权限、容器或数据契约回归。
6. 浏览器和真机均完成截图/录屏级验收后，才具备外出录制条件。

## 4. 已锁定的视觉方案

### 4.1 整体方向：浅色现场工作台

采用“浅色中性底 + 白色内容面 + 深靛蓝主操作”的克制工具风。React 与 Unity 共享语义，而非强求像素一致：网页端强调高密度浏览与处理，手机端强调实景对比和单手操作。

| 语义 | 视觉规则 |
| --- | --- |
| 页面背景 | 浅灰蓝中性色，不使用渐变、摄影图或大面积品牌色 |
| 内容表面 | 白色或近白色，细分隔线，轻阴影仅用于弹层和重要面板 |
| 主操作 | 深靛蓝实色，保证白字对比；同一视图只保留一个最主要实色操作 |
| 次要操作 | 白底边框或浅色文字按钮，不与主操作争夺注意力 |
| 低优先级 | 绿色，并始终带“低”文字 |
| 中优先级 | 橙色，并始终带“中”文字 |
| 高优先级 | 红色，并始终带“高”文字 |
| 处理状态 | 待处理=红/橙提示，处理中=蓝，已解决=绿；全部带中文状态文字 |
| 成功/错误/提示 | 绿/红/蓝灰语义条，图标只用简单几何符号或文字，不引入图标字体 |
| 字体 | 系统中文字体；正文优先清晰，不使用装饰字体或外部字体下载 |

颜色必须满足普通正文可读对比；禁用态仍能辨识但明显不可操作。所有动态颜色采用完整静态样式映射，不在运行时拼接 Tailwind 类名。Tailwind 入口仅保留编译与必要设计令牌，不写组件 CSS 规则。

### 4.2 React 页面结构与交互

**登录页**：浅中性背景，桌面为居中窄卡片，上方产品名和一句“现场问题上报与处理”说明；用户名、密码、登录按钮纵向排列。卡片下明确“本地演示账号由后端环境配置”，不在页面展示真实密码。登录失败在表单内显示，输入保留；请求中按钮禁用并显示“登录中…”，不跳空白页。

**桌面工作台**：

1. 保留左侧导航与顶部栏，但收敛为清楚的产品区、当前“问题管理”入口、实时连接状态、管理员名称和退出按钮。
2. 主内容标题为“巡检问题”，副标题说明查看与处理职责，右侧主操作仍为“刷新”。
3. 标题下放三项紧凑摘要：全部问题、待处理、处理中/已解决合并为一个“处理进度”摘要，数值均从当前授权全量列表计算；不做图表和虚假趋势。
4. 摘要下是独立筛选工具栏：标题/描述搜索框、优先级、状态、清空；结果计数靠近列表，不在多处重复。
5. 问题列表采用白底卡片表格，标题与描述为第一信息列，优先级/状态为标签，更新时间和状态操作右对齐。描述最多两行，完整内容通过可展开详情查看；详情为当前行展开，不另加路由或复杂弹窗。
6. 有未保存草稿的行用浅色背景和“未保存”文字提示；远端更新时明确区分当前服务端状态和用户草稿，保存按钮文案不变。
7. 顶部反馈条按优先级一次只显示最重要的一条；实时连接状态是独立小标签，不与业务错误抢成多层警告。

**窄屏**：小于 768px 时隐藏侧栏，顶部保留产品名、实时状态和账户菜单；摘要允许横向三列紧凑排列但不造成页面横向滚动。筛选项纵向或两列换行。问题表格转换为卡片列表，每张卡片展示标题、描述、优先级、当前状态、更新时间和状态操作；保存按钮全宽或与选择框等宽排列。不得仅靠桌面表格 overflow-x 作为窄屏方案。

**状态与动效**：加载使用结构稳定的骨架占位，避免内容跳动；空态提供“清除筛选”或“刷新”匹配场景的动作。按钮、输入、下拉、行展开均有 hover/focus/active/disabled，键盘焦点清楚。只允许 100～200ms 的颜色、透明度和轻量位移过渡；不使用循环闪烁、弹跳、页面进入大动画。遵循系统减少动态效果设置时不影响信息呈现。

### 4.3 Unity 界面结构与交互

继续使用现有 uGUI、系统字体和 Built-in 渲染，不新增美术资源。所有面板由同一场景搭建规则生成，设计参数集中管理，重复搭建幂等，不手工保存一套与工具不一致的场景。

**登录**：全屏浅中性底，中央卡片包含产品名、用户名、密码、登录按钮和错误区。不显示密码或后端密钥；键盘弹起时登录按钮与错误提示仍可见。已有后端地址配置保留在设置，不塞进首屏登录表单。

**AR 主界面**：

1. 顶部为半透明深色工具条，左侧只显示短后端状态，右侧依次为“历史”“手电”“设置”；文字在明亮实景上仍可读。
2. “重置”不长期占据一级高频位置，放入设置面板的“AR 会话”区，并保留明确说明；避免录屏或单手操作时误清地图。该入口调整是本计划唯一明确的控件位置变化。
3. 顶部工具条下方只保留必要的会话/跟踪提示；正常跟踪时缩短为一行，不长期覆盖实景。
4. 底部显示当前任务提示，例如“点击蓝色平面放置标记”；有草稿时改为“已放置标记，可点标记旁按钮上报”。
5. 标记旁的“上报此标记”跟随按钮保持世界投影跟随和出屏隐藏，使用高对比实色与足够触控面积，不遮挡标记中心；投影逻辑不改。
6. 开发构建黄色调试条遵循“完整诊断”开关：默认隐藏且不周期采样，仅排错主动开启时显示；开启状态下录制需注明其为诊断信息，不伪造为正式业务 UI。

**上报表单**：底部大圆角卡片 + 全屏半透明蒙层。顶部为“上报问题”和取消，下面依次是标题、描述、优先级三选一、只读坐标、主提交按钮。优先级采用三个并排选择项，文字和颜色同步；不依赖系统下拉的小字号。坐标弱化但完整可读。提交中禁用并显示进度；失败时错误位于按钮上方且表单/草稿不丢。键盘弹起时内容区域可滚动，标题、优先级、提交按钮至少能通过滚动到达，不被键盘永久遮挡。

**历史与设置**：采用全屏页面而非狭窄小弹窗，统一顶部返回、标题和右侧主操作。历史使用卡片列表，状态/优先级标签与 React 同语义；卡片内描述、坐标和时间层次清晰。加载、空、失败和过期均保留结构。设置分为后端地址、账号、诊断与 AR 会话四区，保存/退出/重置使用不同视觉等级；危险或破坏性操作使用文字确认，不只用红色。“完整诊断”开关默认关闭，旁边明确其会启用详细设备日志和放置实景/坐标记录；不把诊断状态伪装成普通通知开关，也不因界面美化删除说明。

**触控与安全区**：主要按钮触控高度不低于 48dp，输入和优先级控件不低于 44dp，卡片正文不小于 14sp，关键按钮 16sp。顶部与底部适配 Android 状态栏、手势区和相机打孔安全区；不以固定像素硬凑单台设备。横屏不属于本期，继续保持竖屏。

### 4.4 图标与装饰边界

不引入图标库。仅使用文字和 uGUI/CSS 可表达的简单几何形状，例如连接状态圆点、优先级色条、下拉箭头。禁止字符画、大面积渐变、玻璃拟态堆叠、无意义插画、发光 AR 标记和粒子特效。AR 标记继续保持简单几何体，只使用计划 006 已确定的优先级颜色，避免户外过曝和遮挡命中点。

## 5. 旧界面去向与功能冻结

| 既有内容 | 本计划处理 |
| --- | --- |
| React 基础侧栏、顶栏和列表卡片 | 保留信息结构，替换为统一工作台视觉；不并行保留新旧两套外壳 |
| React 桌面表格横向滚动窄屏方案 | 窄屏替换为卡片列表；桌面仍保留表格 |
| React 页面顶部多条状态文字 | 统一为单条主反馈 + 独立实时连接标签；错误详情不隐藏 |
| Unity 默认灰色控件与分散文字样式 | 替换为集中设计参数生成的统一 uGUI 样式 |
| Unity 顶部“重置”一级按钮 | 移至设置面板 AR 会话区，功能与确认逻辑保留，不并存两个入口 |
| Unity 表单系统优先级下拉 | 替换为三项分段选择；提交枚举映射保持一致 |
| Unity 历史/设置基础面板 | 改为全屏统一页面，保留原控制器职责和回调 |
| AR 平面、标记、跟随按钮 | 只调整视觉样式；世界坐标、投影、出屏隐藏和锚点逻辑不变 |
| 开发诊断与日志 | 保留开发构建排错用途与全部代码；屏幕调试条和日志由默认关闭的完整诊断开关统一控制 |

功能冻结条款：施工发现功能缺失时，记录并退回计划 006，不在本计划临时加接口或改业务。只允许为可用性补充展示状态、焦点、滚动、文本和控件位置；所有业务判断复用既有状态。

## 9. 风险与处理
