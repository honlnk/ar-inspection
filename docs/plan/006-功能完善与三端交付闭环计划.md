## 4. 已锁定的产品与技术方案

### 4.1 本地演示账号与权限

采用两个环境变量初始化的本地演示账号，用户名固定为 `inspector` 和 `admin`，显示名分别为“巡检员”和“管理员”。密码只从后端环境读取，仓库示例统一使用 `[REDACTED: 本地演示密码]`，实际值写入未跟踪的本地环境文件。启动缺少任一密码或会话密钥时明确失败；不为开发环境设置可猜测的默认密码，也不为本地演示关闭鉴权。

角色规则：

| 能力 | 巡检员 | 管理员 |
| --- | --- | --- |
| 查看问题 | 仅自己创建的问题 | 全部问题 |
| 创建问题 | 允许，服务端绑定当前用户为创建人 | 不允许 |
| 修改处理状态 | 不允许 | 允许 |
| 修改标题、描述、优先级、坐标 | 不允许 | 不允许，本期无内容编辑 |
| WebSocket | 不连接，Unity 使用 REST 历史列表 | 连接，事件范围与全量列表权限一致 |

采用随机不透明会话令牌和持久会话记录，不在这轮引入 JWT 刷新令牌体系。浏览器使用 `HttpOnly`、`SameSite=Lax` Cookie，本地 HTTP 不设置 Secure；Unity 使用同样的登录接口保存会话 Cookie。跨域只放行明确的本机/容器管理端来源并允许凭据，不使用通配符。会话有效期 12 小时，退出立即撤销；过期或撤销后，REST 和 WebSocket 均返回未认证，React 回到登录页，Unity 保留未提交草稿并引导重新登录。

密码以强哈希保存，不明文落库、不写日志。登录失败统一提示“用户名或密码错误”，不暴露账号是否存在。用户和会话表由幂等初始化创建；首次启动根据环境变量建立或更新两个演示账号，旧问题没有创建人时保留给管理员可见，巡检员不可见，不猜测归属、不清空数据。业务问题响应不新增归属字段，权限在服务端过滤；历史列表的“我的问题”依赖同一授权规则。

新增接口锁定如下：

| 方法与路径 | 用途 | 主要结果 |
| --- | --- | --- |
| `POST /api/auth/login` | 用户名密码登录 | 返回当前用户显示名和角色，并设置会话 Cookie |
| `POST /api/auth/logout` | 退出并撤销会话 | 返回成功，清除浏览器 Cookie |
| `GET /api/auth/me` | 恢复登录状态 | 有效返回用户，无效返回未认证 |
| `GET /api/issues` | 按当前角色返回授权范围列表 | 字段与既有问题契约完全一致 |
| `GET /api/ws` | 管理员建立 WebSocket | 鉴权失败不升级连接 |

登录请求同样限制请求体、拒绝未知字段；未认证统一 `401 authentication_required`，已认证但角色不允许统一 `403 permission_denied`。健康检查保持匿名且不含敏感信息。既有创建、列表、状态接口改为受保护接口，错误响应继续使用统一中文结构。

### 4.2 React 实时同步

后端仅在 SQLite 事务成功提交后发布 `issue.created` 或 `issue.updated` 事件，事件正文使用完整、既有八字段问题对象，不发送密码、令牌或创建人信息。所有连接由同一后端进程管理；本期单进程，不引入 Redis。使用成熟 Go WebSocket 库处理帧、关闭和写超时，浏览器使用原生 WebSocket；不写自制协议解析器。

React 同步规则：

1. 登录管理员后获取全量列表，再建立 WebSocket；连接地址由后端基础地址转换，不另写死端口。
2. 收到事件先校验运行时结构。新增按后端稳定排序插入，修改按 ID 替换；未知 ID 的修改触发一次全量校准，不伪造行。
3. 每条事件携带单调递增的本进程序号；客户端只接受更晚事件。检测到重复直接忽略，检测到跳号或重连立即全量校准；进程重启造成序号回退时以新连接后的全量列表为准。
4. 列表请求、保存请求和事件应用必须串行合并到同一份状态；自动事件不得取消正在进行的保存，也不得把服务端尚未确认的目标状态当成成功。
5. 某行存在未保存草稿时，远端更新该行只更新“当前服务端状态”，保留用户选择和明显的“远端已更新，草稿未保存”提示，用户仍可保存或放弃草稿。
6. 顶部显示“实时已连接 / 正在重连，数据可能不是最新 / 会话已过期”。断线采用有限退避自动重连，重连先全量校准；手动刷新始终可用。
7. WebSocket 鉴权失败或持续不可用时，REST 仍可工作并明确显示降级状态；不得白屏、清空旧列表或循环刷登录页。

必须有事件序测试覆盖：创建后更新、更新先于创建到达、重复事件、乱序响应、断线重连、保存期间远端修改同一行、过期会话。测试使用可控假 socket/时钟，不把真实网络偶然时序当稳定单元测试。

### 4.3 Docker 与局域网启动

提供多阶段后端镜像和管理端镜像：后端从固定 Go 工具链构建非 root 运行镜像，管理端构建 React 静态产物并由固定 Nginx 镜像提供服务。Node/pnpm 版本与锁文件一致；镜像支持本机 arm64，不要求用户额外模拟 x86。依赖下载使用锁文件和缓存，不复制本机依赖目录、数据库、密钥、Unity Library 或构建产物。

Compose 只包含后端、管理端两个长期服务及一个 SQLite 命名卷：

- 后端容器监听 8080，SQLite 写入命名卷，健康检查真实调用既有健康接口。
- 管理端容器映射 5173，提供静态页面，并将同源 `/api` 请求代理到后端；React 构建和运行不再依赖宿主机 localhost 才能访问后端。
- 容器后端仍监听所有网卡；手机使用 `http://<电脑局域网IP>:8080`，与直接运行 Go 的配置方式一致。
- 实际密码和随机会话密钥通过未跟踪的 Compose 环境文件注入；示例文件只含占位符。
- 容器停止再启动后命名卷数据仍在；删除卷属于用户显式清理动作，启动命令不得自动删卷。
- 镜像构建不下载 Unity、不包含 APK，不把 Docker 当成 Unity 构建环境。

README 同时保留本机开发和 Docker 两套步骤，明确 Docker Desktop 前置、首次构建耗时、局域网防火墙、数据卷位置语义和清理方式。验收必须在全新临时卷上启动一次，再停止、启动复核持久化；不使用开发者现有正式数据库掩盖初始化问题。

### 4.4 React 筛选

筛选完全在已获得的服务端授权列表上进行，不新增查询接口、不改动问题契约。标题搜索去首尾空白、忽略大小写，匹配标题和描述；优先级与状态各提供“全部”及三个枚举选项。三个条件同时生效，列表标题显示“显示 X / 共 Y 条”，一键清空恢复全部。

筛选不改变行顺序、不发状态保存、不丢弃其他行的未保存草稿。实时事件使数据变化时按当前条件重新计算可见行；正在编辑的行即使被筛出也不丢草稿。空结果显示“没有符合当前条件的问题”，与后端无数据和加载失败明确区分。无分页；本地原型数据量下不做虚拟列表。

### 4.5 AR 优先级标记样式

保持当前单草稿、黄色立方体的几何形状和锚点，只将颜色改为优先级语义：低=绿色、中=橙色、高=红色，并提供文字/表单同步，不只靠颜色传递含义。放置时使用表单当前优先级；表单内切换优先级立即改变已放置草稿颜色；打开表单、切换、失败重试、取消、成功清除全链路保持一致。

优先级是未提交草稿的本地编辑状态，不上报前不写后端。请求体仍以提交时优先级为准，坐标、锚点、世界锁定和点击位置不得因换色变化。材质实例不得在每次切换时泄漏；使用共享材质或明确释放实例。场景搭建幂等，重复执行不新增重复材质或破坏既有 UI 接线。

### 4.6 Unity 历史问题列表

顶部新增“历史”入口，与“设置”并列。面板包含当前账号、刷新、退出和按创建时间倒序的问题列表；每条显示标题、优先级、状态、描述、三维坐标、创建/更新时间。首版只读，不允许从历史记录修改状态或恢复 AR 标记。

进入面板手动拉取一次，之后以“刷新”按钮更新，不做轮询或 WebSocket。请求期间保留旧列表并显示加载状态；首次失败显示错误和重试，刷新失败保留旧数据并提示可能过期；空列表显示“暂无历史上报”。会话过期时保留面板和未提交草稿，跳转登录，不把它显示成空列表。

面板打开时冻结 AR 放置，关闭后恢复；所有滚动、输入和按钮均通过既有 UI 防误触路径。Unity 登录采用独立全屏面板，启动时先恢复有效会话，失败再要求登录；未登录不能进入 AR 上报主界面。管理员账号登录 Unity 时明确提示“请使用巡检员账号”，不显示可上报的空壳界面。React 则仅允许管理员进入管理台，巡检员账号在网页端提示角色不适用。

### 4.8 运行时诊断开关

设置面板新增“完整诊断”开关，首次安装和升级均默认关闭，状态持久保存，重启 App 保留。该开关管运行时采集与详细日志，不再以“开发构建”等同于“持续输出所有诊断”。

| 内容 | 默认关闭 | 开启完整诊断 |
| --- | --- | --- |
| 屏幕调试条与周期采样 | 隐藏，不执行每 0.5 秒的平面、按钮、相机姿态诊断输出 | 恢复现有调试条、点击判定、平面和相机姿态日志 |
| 创建问题网络日志 | 不输出完整请求体和成功响应详情；保留不含凭据的失败阶段或状态码摘要 | 保留现有详细链路日志，但账号、密码、会话令牌和 Cookie 永远脱敏 |
| 成功放置诊断 | 不新增实景截图和结构化坐标文件 | 沿用现有 PNG/JSON 记录和手工导出，不自动上传 |
| 业务反馈与关键故障 | Toast、校验、上报结果及 Unity 警告/错误继续保留 | 相同，不额外刷屏 |
| 编辑器构建与自动化测试日志 | 保持现有完整输出，便于解释和排错 | 相同，不受手机端开关影响 |

所有详细运行时输出通过统一诊断入口判断开关，不能零散绕过后继续周期刷日志。关闭后停止后续采集，已有历史诊断文件不自动删除，由用户显式清理；开关状态变化输出一条不含敏感信息的必要状态日志。测试日志源码、既有证据、复盘和历史调查记录全部保留，不用条件编译删代码，也不改写历史结论。

完整诊断涉及现场实景与位置，设置开关旁明确说明“仅在排错时开启，会记录设备日志；开启后的放置诊断包含实景截图与坐标”。录屏前默认关闭，需展示排错能力时再主动开启并告知画面内容。验收分别覆盖首次启动默认关闭、开关即时生效、重启保留、关闭后无周期日志/无新增诊断文件、开启后恢复采样，以及关闭状态下网络错误和 AR 异常仍可定位到必要故障。

### 4.9 三端闭环与录制脚本

使用独立临时数据库完成施工验收，不污染演示数据。正式演示前另建干净演示数据，保留 2 条不同优先级、不同状态的预置问题，由 Unity 现场创建第 3 条；不使用模拟工具冒充真机上报。

录制脚本锁定为两段：

1. 手机视频：巡检员登录 → 扫描真实水平平面 → 点击放置 → 切换优先级并展示标记颜色 → 填写并提交 → 成功提示 → 历史列表出现该问题。
2. 电脑视频：管理员登录 → 展示手机刚上报的问题自动出现（保留一次手动刷新兜底）→ 按标题/状态筛选 → 修改状态并保存 → 重启 Go 或容器 → 页面恢复后会话、问题和修改状态仍在 → 手机历史刷新显示最新状态。

脚本不承诺 WebSocket 永不断线；若录制时降级，必须如实展示重连/刷新并保留说明。视频录制本身属计划 007 收尾后的用户动作，本计划只交付可执行脚本、稳定功能和室内真机证据。
