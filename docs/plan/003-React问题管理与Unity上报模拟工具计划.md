## 1. 计划目标

本计划把静态 React 管理台推进为可用的问题管理页面，同时增加一个独立的 Unity HTTP 上报模拟工具，在进入真机 AR 开发前隔离接口契约、数据链路和网页交互问题。

本期完成后，应当能够只使用 Go 后端、React 管理端和模拟工具完成：

1. 模拟工具通过真实 HTTP 上报包含标题、描述、优先级和三维坐标的问题。
2. React 首次加载及手动刷新后展示同一条问题。
3. 管理人员在 React 中修改处理状态，页面与后端保存结果一致。
4. 后端停止并重启后，React 仍能查询到原问题和修改后的状态。
5. 后端不可用、请求超时、响应异常和状态保存失败时，页面可理解、可操作，不白屏、不伪造成功。

模拟工具只替代 Unity 的 HTTP 输入来源，不替代 Unity 真机、AR 平面检测、射线命中、移动端表单或 Android 网络验收。本期通过不代表完整三端闭环已经完成。

### 4.1 技术与工程决策

| 决策项 | 本期规则 |
| --- | --- |
| React 数据请求 | 使用浏览器原生 fetch，扩展现有请求基础模块 |
| React 状态 | 使用函数组件和 Hooks，不引入外部状态库 |

| 联调数据 | 使用临时 SQLite 文件和独立空闲端口，不接触开发者正式数据库 |
| 远程操作 | 不 push、不创建 PR，不改写已有 Git 历史 |

新增测试依赖只用于开发验证，不进入产品运行时。安装后以实际锁文件更新 README 中的验证命令，不凭建议值填写精确版本。

### 4.2 React 页面与字段展示

页面保留现有信息结构，不增加导航入口。顶栏的“骨架阶段 · 未接数据”替换为中性的“问题管理”，不展示未经健康检查证实的在线状态。

| 页面元素 | 展示与行为 |
| --- | --- |
| 标题行 | 保留“问题列表”和说明文案，右侧为可用的“刷新”按钮 |
| 数量 | 只有列表请求成功后显示实际数量；首次加载和首次失败显示“共 — 条”，不将未知数据写成 0 条 |
| 标题 | 显示完整标题，长文本换行且不撑破页面 |
| 描述 | 在标题单元格内显示描述内容；空描述显示“无描述”；不增加详情页 |
| 优先级 | 显示“低 / 中 / 高”，分别对应 `low / medium / high`，通过静态类名映射颜色 |
| 当前状态 | 显示“待处理 / 处理中 / 已解决”，分别对应 `open / in_progress / resolved` |
| 状态编辑 | 操作列使用原生下拉框，选项值保持三个后端枚举；切换选项不立即请求 |
| 更新时间 | 显示服务端 `updatedAt` 对应的北京时间，不显示浏览器生成时间 |
| 保存 | 每行独立“保存”按钮；草稿与服务端当前状态相同时禁用 |
| 坐标 | 首版管理列表不展示，仍由请求和响应类型完整保留 |
| 窄屏 | 页面本身不横向溢出；表格在卡片内部横向滚动，沿用现有响应式侧栏规则 |

描述采用完整文本换行展示，避免仅提供依赖鼠标悬停才能阅读的内容。首版不限制后端已有描述的长度，不在前端截断后伪装成完整内容。

### 4.3 React 交互与状态规则

#### 首次加载与刷新

1. 首次进入页面立即请求列表，加载期间显示“正在加载问题”，不显示空列表文案。
2. 请求成功后替换页面问题数据；空数组显示“暂无问题”，请求失败不能进入空列表状态。
3. 手动刷新期间按钮显示“刷新中…”并禁用；已有列表继续可见，不用整页加载遮挡旧数据。
4. 刷新成功后，仍在列表中的问题保留用户尚未保存的状态选择；新数据的其他字段以服务端为准。
5. 刷新失败时保留旧列表，显示“刷新失败，当前数据可能不是最新数据”和重试入口。
6. 首次加载失败时不显示虚构列表，显示明确错误和“重试”按钮，页面外壳仍完整可用。
7. 同一时刻只允许一个列表请求；首次加载或刷新期间禁用全部状态编辑与保存，直到列表请求结束。组件卸载后取消请求并忽略迟到结果。

#### 状态编辑与保存

1. 每行草稿初始等于服务端当前状态；用户只修改下拉框时不发送请求。
2. 点击保存后仅发送 `{ "status": "..." }`，不提交标题、时间或其他字段。
3. 为降低首版并发状态复杂度，同一时间只允许一笔状态保存。保存期间禁用全部状态下拉框、保存按钮和刷新按钮，并显示正在保存的问题。列表请求期间同样禁用状态编辑与保存。
4. 保存成功后，以服务端返回的完整问题替换对应行，草稿同步为服务端状态，并显示“问题「标题」状态已更新为「目标状态」”。列表顺序保持不变。
5. 保存失败时保留原问题及服务端当前状态，保留失败行和其他行尚未保存的草稿，不用旧响应覆盖用户选择。
6. 保存失败显示问题标题和后端中文错误；网络失败显示可理解的连接或超时提示。失败后直接在原行再次点击保存即重试，不自动重发，不额外增加重复的重试按钮。不得先把失败状态展示为成功。
7. 问题不存在、参数错误和服务器错误都按失败处理，不自动重复写入。
8. 保存成功提示保留到下一次刷新、状态编辑或保存操作开始时，不使用自动消失计时器。
9. 后端返回非法问题结构、空数据或成功结构缺失时，按异常响应处理，不直接渲染并导致白屏。

本期通过串行化“列表请求”和“状态保存”避免互相覆盖：列表请求期间不能开始保存，保存期间不能刷新。无需引入请求版本号或复杂缓存系统。

### 4.4 反馈文案与位置

反馈统一放在标题行下方、问题卡片上方；表格内部只保留加载、空列表或首次失败的行内说明。不得同时出现互相矛盾的“加载中”“暂无数据”和“请求失败”。

| 场景 | 必须表达的信息 |
| --- | --- |
| 首次加载 | 正在从后端加载问题 |
| 首次失败 | 无法获取问题、可理解原因、重试按钮 |
| 空列表 | 后端连接成功，当前没有问题 |
| 刷新 | 正在刷新，旧数据继续可见 |
| 刷新失败 | 旧数据可能不是最新数据，可重试 |
| 保存中 | 哪一条问题正在保存 |
| 保存成功 | 哪一条问题更新为哪个状态 |
| 保存失败 | 哪一条问题未更新、失败原因、保留原行选择并可再次点击保存 |
| 异常响应 | 后端返回的数据格式不正确，不暴露堆栈或整段响应正文 |

错误区域使用可感知的状态或警报语义；按钮具有明确文字，不只使用图标。所有操作均可通过键盘完成。

### 4.5 模拟工具的命令与行为

工具名称定为 `issue-reporter`，位于 `tools/issue-reporter/`。工具是开发辅助程序，不是正式产品端。

提供两个子命令：

| 子命令 | 用途 | 成功结果 |
| --- | --- | --- |
| `create` | 按给定标题、描述、优先级和坐标调用创建接口 | 输出后端完整成功响应，退出码为 0 |
| `list` | 调用列表接口 | 输出后端完整列表响应，退出码为 0 |

两个子命令均接受后端地址和超时参数，默认后端地址为 `http://localhost:8080`，默认超时为 10 秒。创建命令支持以下参数：

| 参数 | 规则 |
| --- | --- |
| 标题 | 原样发送，默认空字符串，便于验证空标题错误 |
| 描述 | 原样发送，默认空字符串；创建请求始终包含该字段 |
| 优先级 | 默认 `medium`，原样发送，不替用户纠正非法枚举 |
| 三轴坐标 | 默认均为 0，接受零、负数和小数；本地拒绝 NaN 和无穷值 |

典型调用形式：

```bash
cd tools/issue-reporter
go run . create -base-url http://localhost:8080 -title "模拟上报：入口墙面破损" -description "非 AR 工具创建" -priority high -x 0.42 -y 0.03 -z 1.26
go run . list -base-url http://localhost:8080
```

工具行为锁定如下：

1. 创建只发送 `title/description/priority/position` 四类客户端字段，位置保持嵌套结构。
2. 成功和接口错误均输出可读的完整 JSON；本地参数错误、连接失败、超时和响应结构错误输出明确中文诊断。
3. 成功响应必须包含合法数据外层；创建结果必须包含非空 ID、默认 `open` 和服务端时间，否则按响应契约失败。
4. 列表结果必须是数组，空数组合法；不得将请求失败或格式错误显示为空列表。
5. HTTP 成功且契约检查通过退出码为 0；HTTP 错误、网络错误、超时和契约错误退出码为 1；命令用法错误退出码为 2。
6. 工具不自动重试创建，避免超时后重复上报；列表也不在失败后自动循环请求。
7. 工具不生成模拟 ID、状态或时间，不在本地缓存响应，不读写 SQLite。
8. README 和工具帮助文案明确标注坐标为人工输入的模拟坐标，不代表真实 AR 位置。
