## 1. 计划目标

修复真机上“蓝色平面与真实表面错位、黄色标记落在触点下方或屏幕外”的已知问题，使手机的真实运动能够驱动 Unity 渲染相机，平面和标记在真实环境中正确对齐。

本计划完成后必须同时证明：

1. 手机平移和转动时，Unity 相机位置与旋转持续随之变化，不再停留在初始姿态。
2. 点击已检测平面后，标记位于实际命中位置；其屏幕投影接近触点，而不是系统性偏移或出屏。
3. 移动与绕动手机时，已放置标记保持在原真实位置，平面可视化与真实表面对齐。
4. 场景接线、工程初始化与重新搭建运行时内容使用同一套正确配置，不会重新引入旧驱动。
5. 既有 UI 防误触、表单、后端地址配置和 HTTP 上报能力不回归。
6. 真机验证证据能够区分“组件配置正确”与“设备姿态确实进入相机”，不再以编辑器模拟或内部投影自洽替代真机验收。

## 4. 已锁定的技术方案

### 4.1 相机输入链路

| 决策项 | 本计划规则 |
| --- | --- |
| AR 输入管理 | 在 AR Session 同对象添加且只添加一个 AR 输入管理器，由编辑器场景工具持久化到主场景 |
| 相机姿态驱动 | 使用 `UnityEngine.InputSystem.XR.TrackedPoseDriver`；主相机只保留这一个姿态驱动 |
| 位置绑定 | 按当前包官方移动 AR 创建逻辑配置：头戴设备中心眼位置作为兼容绑定，手持 AR 设备 `devicePosition` 必须存在且启用 |
| 旋转绑定 | 按当前包官方移动 AR 创建逻辑配置：头戴设备中心眼旋转作为兼容绑定，手持 AR 设备 `deviceRotation` 必须存在且启用 |
| 驱动更新 | 使用当前包官方移动 AR 创建逻辑的默认更新方式；施工时核对序列化配置，不自行发明分帧补偿或双驱动 |
| 输入资产 | 使用驱动内嵌的位置/旋转动作并随组件序列化；首版不新增全局输入资产，不改动旧触摸输入 |
| 初始化来源 | 直接引用已安装 Input System 类型，不再通过字符串查找已弃用组件并静默回退 |
| 场景生成 | 工程初始化与运行时搭建共用同一个相机输入配置方法，避免两份逻辑再次漂移 |
| 错误处理 | 缺包、缺组件或绑定创建失败必须让编辑器工具明确失败，禁止无警告继续生成“看似完整”的场景 |

上述绑定名称是技术实施约束，正文解释以官方包源码为最终依据；如当前包与既有调查证据不符，停止施工并记录差异，不改用旧驱动兜底。

### 4.2 自动化防回归

阶段门禁必须从“存在一个名字相近的姿态组件”升级为精确检查：

1. AR Session 同对象有且仅有一个 AR 输入管理器。
2. 主相机有且仅有一个 Input System 版姿态驱动。
3. 主相机不存在旧版空间跟踪驱动或已弃用 AR 姿态组件，也不存在其他重复姿态驱动。
4. 位置与旋转输入均启用，手持 AR 设备的两条必需绑定存在，输入动作随场景正确持久化。
5. 原有 AR 管理器、UI、诊断与业务接线检查继续通过。

优先用可重复执行的编辑器验证覆盖序列化配置。若新增纯配置构建逻辑适合抽出为可测试单元，可补 EditMode 测试；不为了凑测试数模拟 ARCore，也不把“输入绑定存在”写成“真机姿态已验证”。

### 4.3 真机观测与验收口径

1. 沿用开发构建放置诊断 PNG/JSON；每个新记录必须能够与具体操作、应用构建时间和截图对应。
2. 修复后先做不点击的相机运动冒烟，再做放置；避免只拿到放置后的单帧数据而无法证明持续运动。
3. 在不放置的情况下，分别执行纯平移和原地转动。诊断或日志须以可区分前后事件的采样，证明相机位置/旋转不再固定；采样不自动上传。
4. 点击放置时同时保留触点、命中点、标记投影和相机数据；命中点与标记世界坐标应一致，投影应接近触点。
5. “接近触点”以正常透视和标记体积为前提，不要求立方体所有可见像素都落在触点上。标记中心不得再出现修复前那种固定向下的大幅偏移或无合理原因的出屏；若仍有偏差，保留 JSON 数值和截图，不用肉眼一句“差不多”验收。
6. 世界锁定用真机操作和截图验证：标记在视野内保持于真实命中表面，移动手机只改变观察角度与近大远小；不把正常移出视野当成漂移。
7. 阶段门禁全绿只是施工门禁，最终关闭问题必须依赖真机结果。

### 4.4 构建、证据与设备设置

- 沿用现有 Android 开发构建入口，不新增第二套构建脚本；构建日志中不得出现编译错误。
- 安装新版本前记录旧版状态，安装后确认应用更新时间和新进程，避免把旧包行为当成修复结果。
- 真机证据存放在 `docs/evidence/005-unity-camera-pose-fix/`；只选择验收所需截图与脱敏说明，不全量导入手机诊断目录。
- 实景截图先人工检查再入库；结构化数据如包含不必要的环境信息，则摘录必要指标到说明文档，不直接提交原始整套记录。
- 若测试需要临时修改手机保持常亮设置，测试结束执行 `svc power stayon false` 恢复，并记录结果；未连接设备时明确列为待用户恢复，不得默认已经恢复。
- 后端回归使用独立临时 SQLite 文件与独立端口；结束后清理自建进程和临时数据，不影响正式数据。

## 6. 分阶段施工与门禁

### 阶段 0：基线与修复前证据

施工内容：

1. 执行第 2.1 节开工门禁，记录 Git、Unity 包、设备与测试结果。
2. 读取当前主场景，确认旧驱动与缺失输入管理器仍存在；保留配置证据。
3. 核对复盘 002 的五组真机数据与官方包源码，建立“缺陷配置—冻结姿态—偏移现象”的基线，不重新开展无方向试参。
4. 检查现有诊断能否支持第 4.3 节的平移/转动采样；若足够则不增加新日志。

阶段门禁：基线测试全绿、根因和官方接线再次核对、真机与环境可用、修复前状态已记录。未满足不得修改场景。

### 阶段 1：统一配置与场景修复

施工内容：

1. 在编辑器工具中实现第 4.1 节的统一 AR 输入配置；失败时显式报错。
2. 工程初始化、运行时搭建与当前场景共用该配置，删除旧驱动与弃用组件回退。
3. 保存主场景并检查序列化结果，确认输入管理器、唯一驱动和两组位置/旋转绑定实际写入。
4. 连续执行两次相关搭建/初始化验证，第二次不得新增重复组件、清除既有业务接线或恢复旧驱动。全量初始化可能覆盖业务场景，只在可控验证副本中做全量回归；正式工程只执行保留业务的增量搭建，并记录这个限制。

阶段门禁：Unity 编译无错误；场景配置精确符合方案；重复执行幂等；业务场景未被全量初始化覆盖。

### 阶段 2：自动化门禁与 Android 构建

施工内容：

1. 扩展阶段门禁，使其对旧配置会失败、对新配置会通过；必要时在临时场景/工程副本验证负例，不故意破坏正式场景。
2. 复跑全部 EditMode 测试与阶段门禁，确保原有业务契约和接线没有回归。
3. 同步构建脚本中已被交叉验证推翻的归因注释；保持 OpenGL ES 3 和既有构建设置。
4. 构建 Android 开发包并核对产物时间、构建结果；安装到真机，确认新版进程启动。
5. 进行编辑器模拟冒烟，确认原有模拟验证路径没有被新的输入配置破坏；其结果不能替代真机。

阶段门禁：EditMode 全绿、阶段门禁全绿、负例检查有效、Android 构建与安装成功、真机新版可启动。任一项失败不得宣布空间问题已修复。

### 阶段 3：真机相机姿态与空间对齐验收

施工内容：

1. 启动新版，在正常光照与有纹理的水平表面上缓慢扫描，等待会话跟踪和平面稳定。
2. 分别平移与转动手机，采集运动前后的相机姿态；确认相机位置/旋转随真实运动变化，且无持续输入异常。
3. 点击平面放置标记，导出同组截图与 JSON：核对触点、命中点、标记世界坐标、屏幕投影、相机姿态和跟踪状态。
4. 在不同距离和持机俯角下至少完成三组有效放置，包含一次偏屏幕中心与一次靠近平面可见边缘的点击；不通过移动 UI 或手工补偿使结果好看。
5. 对同一标记进行平移、绕动、走近/远离，验证真实世界锁定与正常透视；记录平面与真实表面的对齐情况。

## 9. 风险、降级与偏差处理

| 情况 | 处理方式 |
| --- | --- |
| Input System 类型或绑定与当前包源码不一致 | 停止并保留编译/源码证据，不回退旧驱动，不擅自换包版本；将方案差异提交评审 |
| 组件与门禁全绿但相机仍冻结 | 判定真机门禁失败，新增针对输入设备与驱动的运行诊断；不宣布修复，不做射线/投影补偿 |
| 相机已运动但仍有偏移 | 说明存在第二个独立问题；保存新数据并单独评估，不把本计划扩大为无边界排查 |
| 真机放置距离或前方校验误报 | 先确认相机数据已恢复，再记录具体命中与阈值；任何规则调整作为偏差单独说明，不与其他修复混在一起 |
| 暗光、弱纹理或发热导致无法采样 | 改善光照、选择有纹理表面、降温后短测多轮；属于环境限制则记降级，不硬凑通过 |
| 真机不在线或无法移动设备 | 可完成编辑器与构建门禁，但真机验收保持未验证，计划不得完成；由用户执行指定动作 |
| 后台/息屏导致相机失效 | 重启应用恢复并记录，仍属既有独立问题；不在本计划顺手改生命周期 |
| 全量初始化会覆盖业务场景 | 正式工程只做增量配置；全量初始化在验证副本中测试，避免为验证幂等丢失现有业务接线 |
| 手机保持常亮无法由 AI 恢复 | 明确告诉用户在开发者选项中关闭，并列入尾巴；不能默认已恢复 |
| 发现计划外问题 | 写入施工日志与未验证/尾巴清单，不顺手修后端、Web 或扩展功能 |
