## 1. 目标与交付策略

在计划 006 的账号体系上加一层真正的账号管理能力：管理员在网页管理台维护巡检员账号（新增、查看、改显示名、重置密码、删除），新巡检员无需重启后端即可登录 Unity 端上报问题。本计划规模小，目标是把一条完整的管理链路做扎实，不顺手扩展。

本计划完成时必须同时证明：

1. 管理员在网页上新增的巡检员能立即用该账号登录（Unity 与模拟工具同接口），并按既有权限只看到自己的上报。
2. 修改（显示名、密码重置）与删除立即生效：被重置密码或删除的巡检员，其未过期会话在下一次请求即失效。
3. 删除巡检员不丢业务数据：其历史问题原样保留，归属转为未知，仅管理员可见——与计划 006 的历史遗留问题语义一致。
4. 删除的巡检员不会在后端重启后「复活」；管理员账号自身不受本计划管理操作影响。
5. 全部既有自动化检查不回归，新增接口与页面有对应测试；浏览器端完整走通增删改查闭环。

## 3. 本期范围与旧机制去向

### 3.1 本期做什么

| 功能 | 本期交付 |
| --- | --- |
| 巡检员列表 | 管理员查看全部账号（管理员自身以只读形式展示），含用户名、显示名、角色、创建时间 |
| 新增巡检员 | 填写用户名、显示名、初始密码创建，创建后立即可登录，无需重启 |
| 修改巡检员 | 修改显示名；重置密码（重置后该账号所有会话立即失效） |
| 删除巡检员 | 确认后删除账号并踢出会话；其历史问题保留、归属转为未知 |
| 账号初始化语义调整 | 环境变量对巡检员只在首次启动建号；管理员账号保持每次启动按环境变量同步（保留恢复途径） |
| 管理台导航 | 侧栏与窄屏导航增加「人员管理」入口，与「问题列表」切换，不引入路由库 |

### 3.2 本期不做什么

- 不做管理员账号自身的创建、删除、改名或改密（管理员账号由环境变量维护，页面只读展示）。
- 不做角色分配：新账号固定为巡检员，不提供创建第二个管理员的入口。
- 不做巡检员自助修改密码、找回密码；密码变更只有管理员重置一条路径。
- 不做账号停用/启用（软删除）、批量操作、导入导出、按账号统计问题数、分页与搜索排序。
- 不做人员变更的 WebSocket 广播；人员管理页靠操作后刷新与手动刷新，不复用问题事件通道。
- 不改 Unity 端任何代码；Unity 登录、历史列表对新增/删除账号自然生效。
- 不引入前端路由库、组件库或新增第三方依赖（前后端均是）。
- 不改问题八字段契约、权限矩阵、WebSocket 协议与 Docker 架构。
- 不改写历史提交，不 push、不创建 PR；提交与推送等待用户明确指令。

### 3.3 新旧机制替代表

| 现有机制 | 本计划去向 |
| --- | --- |
| 启动时环境变量每次强制同步 inspector/admin 两个账号 | 拆分：管理员保持每次启动同步；巡检员改为「仅库中不存在时创建」，之后完全由管理接口维护（删除后重启不复活） |
| 侧栏单一静态「问题列表」入口 | 替换为「问题列表 / 人员管理」两个可切换入口；切换不卸载问题工作台（保持实时连接与未保存草稿），用显示/隐藏实现，不引入路由 |
| 巡检员密码以 `backend/.env` 为准 | 变更为以人员管理页设置为准（初始密码仅首启来自环境变量）；`TEST-ACCOUNTS.md` 说明同步修订 |
| 问题归属记录无删除路径 | 删除巡检员时在同一事务内清除其归属记录；问题本体保留，转为「归属未知、仅管理员可见」，与历史遗留数据同语义 |
| 同名账号不可重复（库级唯一约束） | 保留：删除后同名可再创建，但属于全新账号，不继承被删账号的历史问题归属 |

## 4. 已锁定的产品与技术方案

### 4.1 账号语义与初始化规则

| 账号 | 初始化 | 密码来源 | 可否在人员管理页操作 |
| --- | --- | --- | --- |
| admin（管理员） | 每次启动按环境变量同步密码与显示名 | `ADMIN_PASSWORD` 环境变量（改后重启生效） | 只读展示，不提供任何操作 |
| inspector（首启巡检员） | 仅数据库中不存在时创建一次 | 首启取 `INSPECTOR_PASSWORD`，之后以管理页为准 | 与其他巡检员相同，可改可删 |
| 网页新增的巡检员 | 由人员管理页创建 | 管理员在新增表单中设定初始密码 | 可改可删 |

管理员账号保持环境变量同步的理由：这是本地演示项目唯一的恢复途径（忘记管理员密码时改环境文件重启即可），且不涉及业务数据。巡检员改为业务账号：增删改查的管理语义要求「删除就是删除」，环境变量每次同步会让被删账号重启复活，与管理操作冲突。

用户名在创建后不可修改（登录身份，且问题归属按用户名派生账号标识）；显示名与密码可改。

### 4.2 接口契约

人员管理接口全部挂载在既有认证体系下：需已登录，且角色必须是管理员（401/403 语义与既有接口一致）。路径用用户名作资源标识（用户名仅限字母、数字、下划线、连字符，天然 URL 安全）。

| 方法与路径 | 权限 | 请求体 | 成功响应 | 失败要点 |
| --- | --- | --- | --- | --- |
| GET /api/users | 管理员 | — | 全部账号列表（含管理员，只读标志由前端按角色判定） | 401/403 同既有语义 |
| POST /api/users | 管理员 | username、displayName、password | 201 + 新账号公开信息 | 用户名重复或非法、密码长度不足、显示名为空 → 400 中文参数错误 |
| PATCH /api/users/:username | 管理员 | displayName、password（均可选，至少一项） | 200 + 更新后账号公开信息 | 目标不存在 → 404；目标是管理员 → 403；字段非法 → 400 |
| DELETE /api/users/:username | 管理员 | — | 204 | 目标不存在 → 404；目标是管理员 → 403 |

响应中的账号公开信息沿用既有三字段结构（用户名、显示名、角色），另含创建时间与更新时间；任何响应不出现密码或哈希。

删除与重置密码的会话联动：删除账号时同一事务内清除其全部会话记录；重置密码时同样清除（下次请求即 401，等价于「立即踢下线」）。仅改显示名时会话保留。

删除的事务顺序：清归属记录 → 清会话 → 删账号，任一步失败整体回滚。

### 4.3 校验规则（前后端一致，后端为准）

| 字段 | 规则 |
| --- | --- |
| 用户名（新增时） | 2～32 位，仅限英文字母、数字、下划线、连字符；不可与现有账号重复（含管理员）；创建后不可改 |
| 显示名 | 去除首尾空格后 1～32 个字符，不可为空 |
| 密码（新增必填、重置可选） | 8～72 位（72 为 bcrypt 算法上限），不可为空 |
| PATCH | 显示名与密码至少提供一项，否则 400 |

所有参数错误返回既有统一错误信封与中文提示（与「标题为空/枚举非法」同一风格）；不区分「用户名已存在」与「用户名非法」以外的存在性探测顾虑（管理页本身仅管理员可见，列表已含全部用户名）。

### 4.4 React 页面与导航

**导航**：侧栏（桌面）与顶部简化导航（窄屏）均提供「问题列表」「人员管理」两个入口。切换用页面级状态控制两个面板的显示/隐藏，问题工作台切走时保持挂载，实时连接、未保存草稿与筛选状态不丢；不引入路由库。

**人员管理页**：

1. 标题「人员管理」，副标题说明职责（维护巡检员账号）；右上角主操作「刷新」。
2. 账号列表为白底表格：显示名（第一列）、用户名、角色标签、创建时间、操作列（修改、删除）。管理员账号行置底或分区展示，操作列显示「系统账号」只读说明。
3. 「新增巡检员」为页面内表单区（三个输入：用户名、显示名、初始密码），不做路由跳转；提交中禁用；成功后清空表单、刷新列表并给出成功提示。
4. 「修改」展开当前行编辑区：显示名输入 + 新密码输入（留空表示只改显示名）；保存中禁用；成功提示并刷新。
5. 「删除」使用行内确认（二次点击确认或确认条），确认文案说明后果：「其历史问题将保留，归属转为未知，仅管理员可见」；删除中禁用；成功后刷新列表。
6. 加载中骨架、空列表（「还没有巡检员账号」）、请求失败（中文错误 + 重试）布局完整；会话过期复用既有处理（回登录页）。
7. 样式沿用现有 Tailwind 工具类与既有表格/表单视觉，不做美化改版（视觉统一留给计划 007）。

### 4.5 闭环验收脚本（桌面可执行）

1. 管理员登录管理台 → 人员管理页看到 inspector（首启账号）与 admin（只读）。
2. 新增巡检员「zhangsan」→ 用模拟工具（issue-reporter，代真机 Unity）以该账号登录并上报一个问题 → 管理台问题列表出现该问题，且用该巡检员会话只看到自己这一条。
3. 管理页修改 zhangsan 显示名 → 人员列表即时更新；问题列表不受影响。
4. 重置 zhangsan 密码 → 旧会话的下一步请求立即 401（模拟工具与接口直连均可验证）。
5. 删除 zhangsan → 其历史问题仍在管理台可见（归属未知语义），巡检员视角不可见；新会话登录报「用户名或密码错误」。
6. 重启后端 → zhangsan 不复活，问题数据原样保留；inspector/admin 按第 4.1 节规则各自保持。
